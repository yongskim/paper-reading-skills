# 跨领域阅读与目录扩展

本套 skill 不绑定学科或研究方向。计算机、工程、自然科学、社会科学及人文学科都按目标论文实际材料组织阅读；领域名称只是背景与归档标签，不是技能的适用范围。

分别识别三个维度：

- **领域/问题背景**：研究对象、术语、常用方法及证据传统。跨领域论文可以有多个标签，不强行选一个学科解释所有内容。
- **研究类型**：方法、实验、观测/实证、定性、评测/数据、综述、理论、论证等，用于选择笔记结构。
- **归档位置**：由用户指定的领域、主题与子目录，可为任意深度。类型判断不能替用户决定目录。

先沿用论文自身定义，必要时补充理解所需的学科背景，并区分补充知识与作者贡献。不把一个领域的术语、默认假设、评价标准或「最好有代码」观念强套到另一个领域。术语跨领域同名时明确当前含义，不能仅因名称接近就判定同一方法。

## 调整解释和证据

保留七部分的阅读功能，允许按学科和研究类型改变标题、子项及篇幅。实证研究重采样、测量和不确定性；定性研究重材料、分析过程和解释依据；理论研究重定义、论证和成立条件。没有算法、训练、Benchmark、统计检验或定理时不强制加入。

来源追查对象可为理论框架、概念定义、量表、实验范式、采样与分析程序、仪器、协议、数据、指标或算法。根据目标论文实际贡献选择实质来源，保留双侧证据；使用某通用工具不等于研究整体继承自它。

按原研究设计判断证据强度。实验、观察、访谈、案例、文本/档案、仿真与数学证明不能互换证据标准，不将一种证据未经论证推广到另一种结论。只整理原文和必要背景，不主动替用户做学科评价或研究决策。

## 多领域目录

本机文献库根应是容纳多个领域的共同父文档；已配置领域只是可发现的已有目标，不是白名单，也不作为默认落点。用户提供新领域或新目录时，检查该路径是否已存在；不存在时只创建用户明确命名的目录及本次需要的画廊/索引。

不要为新领域复制「攻击、防御」等旧领域分类，也不自动批量生成固定分类树。可直接使用领域页或用户选择的主题页作为画廊父文档，不要求每个领域层级相同。同名目录出现在多个领域时，用完整路径确认；用户本次路径已明确就不重复询问。

归档实例配置应区分 library root、domain root 与 gallery parent，保留已有画廊 ID，不因扩大范围重建或搬动原笔记。缓存外的目标按实际目录发现并核验，不能只看配置中的列表。

画廊使用通用字段作为起点：论文、作者、年份、期刊/会议/来源、关键词、研究类型、阅读状态、封面、原文与笔记链接、文献标识。代码、数据、材料、预注册、设备、研究对象等字段按领域与用户需求扩展；不适用时省略或标注不适用，不作负面判断。已有字段和人工值保留，不擅自删列或统一改名。
