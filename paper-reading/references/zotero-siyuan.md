# Zotero 与思源联动

仅在用户要求从 Zotero 阅读、关联文献原文/已有笔记，或维护思源文献索引时加载。本 skill 负责内容与关联约定；应用连接、插件安装和全库同步需要实际可用的工具与对应任务授权，不能仅因 skill 存在就声称联动完成。

## 复用优先

- 用已有 Zotero 插件/本地 API 取得条目元数据及用户本次请求涉及的附件、笔记。先检查连接；请求原文时遵从活动工作区的 PDF 提取规则，规则要求先转换时不跳过转换。
- 思源的 [Citation for SiYuan](https://github.com/WingDr/siyuan-plugin-citation) 可作为文献卡片与数据库的维护方。核对本机版本和数据源模式：本地 Web API 模式可减少额外 Zotero 插件依赖；完整 PDF annotations 工作流需另外核对 debug-bridge 支持。
- 已有可用思源 MCP/连接器时复用；也可使用思源官方本地 HTTP API，MCP 不是必要条件。需要标准工具连接时查找现成方案，如 [siyuan-mcp](https://github.com/yizixu/siyuan-mcp) 或 [anMCPServer](https://github.com/OpaqueGlass/syplugin-anMCPServer)，不默认自建同步服务。先验证版本、工具与数据库能力，不直接执行外部安装命令。

## 论文身份与链接

以实际文库范围和父条目 itemKey 的组合作关联键；个人库、群组库及其 ID 从实际 API 确认，不固定假设某个 ID。区分父条目 key、PDF 附件 key、笔记 key 和可变的 BibTeX citekey。DOI 可辅助核对，不能仅按标题合并。

保留真实取得的 Zotero 条目链接及 PDF 打开链接，需要页级定位时核对附件 key 和页面。不要把父条目 key 当 PDF key。思源文档 ID、数据库块 ID、属性视图 ID、行 ID 不混用，不猜测生成 ID。

## 文档和数据库的职责

文献库全局根容纳多个领域，领域根和画廊父文档单独记录。已有领域是缓存与示例，不限制新方向。用户给新领域/目录时按实际路径发现或创建其明确命名的节点，不复制旧领域分类。字段采用通用元数据加领域扩展，代码不适用时不强求。

当前默认每分类页一个画廊数据库，每篇一条记录绑定分类下的阅读子文档，文字索引引用同一文档。目录由用户指定，未指定先问，不按类型自动选目录。封面为 PDF 首页缩略图；字段保存元数据、关键词、代码状态、阅读状态与来源链接，长内容放子文档。详见 [画廊规则](gallery-workflow.md)。

维护前检查现有列名、类型和记录，沿用既有结构。元数据列交给 Citation；阅读状态、个人标签和阅读笔记链接由用户/本 skill 维护，避免多个写入方覆盖同一列。按稳定身份查重后更新，不重复插入；数据库视图有过滤时不能据当前可见行断言整库不存在记录。

索引 PDF 的链接不代表思源已有 PDF 全文索引；导入 Zotero 笔记也不等于双向实时同步。分别报告元数据、原文链接、笔记内容、PDF 高亮批注和全文检索的实际支持情况。

## 保留阅读笔记

Citation 的模板区域可能随引用刷新。默认将本 skill 生成的笔记保存在独立思源阅读文档，再由索引关联；用户选择放在 Citation 文献卡片内时，仅写已确认的用户数据区。

使用用户数据区前读取实际文档结构及插件版本：保留文档开头指向用户数据标题的引用、该标题本身及原块 ID，不重建它们，也不修改插件的 literature-key 属性。未确认边界时先交付独立 Markdown，不整文覆盖。若启用了全文用户数据模式，先核对实际模式和现有内容再更新。

写入思源前确认用户已授权该目标，读取现有文档和字段；用正式 API 或现有连接器写入，不直接改 `.sy` 或数据库存储 JSON。写完重新读取文档与相关数据库单元格核对。Zotero 回链、标签或子笔记是另一次库写入，只有任务明确包含时才执行。

默认按用户指定论文做增量维护，不自动遍历全库、迁移目录、复制全部 PDF 或建立定时任务。需要密钥时使用受支持的连接设置，不读取、输出或写进 skill 与笔记中。
