# 材料、出处与证据规则

## 客观解释边界

按 [跨领域规则](domain-adaptation.md) 解释术语、研究设计及证据。论文自身定义优先，补充背景需与作者贡献区分；不能把某学科的工具、形式化方式和评价标准默认套用到其他领域。

默认任务是把目标论文讲清楚，把研究判断留给用户。可以解释 Why/How、公式步骤和作者设计理由，不能把自己的猜想写成作者 Insight，或把相关性写成已证实的机制。默认不主动生成最重要弱点、反例清单、研究启发、自检答案或新方案。

作者明确的局限、未报告的评估和能直接核对的事实冲突仍需指出。评价假设合理性或方法适用性时只描述论文给出的理由、前提及验证范围，不把未验证条件直接判断为失效。

## 取得与识别材料

接受本地 PDF、论文链接、已转换 Markdown/JSON、正文摘录和已有笔记。先使用用户已提供或已连接的材料；链接需打开原文，不凭标题或搜索摘要生成全文笔记。只有题目且存在多个候选时先确认论文身份。

核对标题、作者、年份和版本，优先以 DOI/arXiv ID 识别同一论文。预印本和正式版可能不同，记录实际阅读版本，不混用公式或表格编号。

只有摘要或部分章节时完成材料支持的部分，醒目标记覆盖限制，不填造缺失的方法、实验或结论。多个输入冲突时先核查版本并保留冲突说明。

## PDF 转换

先遵从当前工作区 AGENTS.md 的 PDF 规则。若配置了本地 MinerU wrapper，先按配置转换，以生成的 Markdown/JSON 为主要阅读表示。转换产物放在工作区中间文件目录，复用同一原文件及版本的有效结果，避免重复运行。

提取工具路径和后端由活动工作区或明确的本地配置提供；若工作区指定 wrapper 或 CPU pipeline 等约束，按该约束执行。未指定时使用当前可用的 PDF 提取方式并注明处理方式，不假设 MinerU、PowerShell 或固定硬件已安装。配置发现见 [运行配置](runtime-configuration.md)。

图表、公式识别不完整、版面需确认或转换失败时，页面检查作为补充。转换失败记录原因，再使用适用的替代提取或页面检查；不得把摘要当全文。无法取得足够内容时交付可完成部分，说明具体缺失。

不因阅读已提供论文而默认启动外部检索、系统综述或引用审计。需要补充外部知识时，与目标论文内容区分并给来源。

方法溯源是已选择的方法模块的一部分，允许依照 [方法溯源子 skill](../../paper-reading-lineage/SKILL.md) 对关键前作和来源不明的核心组件做定向外部核查。其范围限于解释本文技术来源，不自动扩展为全领域新颖性或诚信审查。用户不允许外查时仅用已有材料，明示未查范围。

## 证据标记

- **原文**：以转述为主，进一步区分「作者声称」「实验在指定条件下支持」「理论在明确前提下成立」。不能因作者写出某句话就将其当作已经验证的事实。
- **解释**：直觉、补充推导、例子或机制分析，说明额外假设。
- **待核实**：材料缺失、识别含混、分析猜想或尚未复核的旧笔记。
- **用户批注**：用户真实提供的判断、疑问和想法，保留原意。

不要求每句话贴标签，在容易混淆时分开陈述。数字、贡献、关键机制、定理前提和证据判断需有定位。

保留指标方向、单位、Baseline、实验设置和必要的资源/威胁模型条件。相对改善百分比与百分点分开；若计算原文未直接给出的差值，标明是据原数值计算。不根据均值差异宣称统计显著，不把有限实验称为普遍证明。

优先用「章节 + 图/表/公式编号」；可信页码可附加，并区分 PDF 页序与印刷页码。没有页码映射时用可搜索的小节、图表编号或短语，不猜页码。内部笔记也应能追到原始材料，不只链接另一份摘要。

更新时不把推断自动升级成事实。旧笔记与原文冲突时明确订正依据，保留用户原批注并附更正说明。
