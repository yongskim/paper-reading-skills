# 思源 Markdown 与公式格式

目标是交付可导入思源的 UTF-8 Markdown 源文件并保留公式源码。不要把聊天中渲染的公式截图、HTML 或复制后的视觉效果视为思源兼容验证。

## 文档结构

- 文档标题用一个 `#`，七部分用 `##`，子项用 `###`。保留章节编号便于继续补充。
- 正常使用段落、简短列表和必要表格。标题、正文、列表、表格之间留空行，减少深层嵌套。
- 论文信息用普通文本，不默认用 YAML frontmatter 或 Obsidian 属性语法。
- 出处直接写 `Section 3.2`、`Figure 2`、`Table 1`、`Equation (4)`，保留原编号。来源链接用标准 Markdown，不输出工具内部引用标记。
- 不编造 `siyuan://blocks/...`、`((块ID))` 或 `.sy` 文件。真实思源引用可保留，未知目标用来源链接或文本定位。

## 行内公式

使用 `$...$`，定界符内部紧贴公式，不加首尾空格：

```markdown
输入为 $x \in \mathbb{R}^{d}$，模型输出为 $f_{\theta}(x)$。
```

不要用 `\(...\)`。代码标识符或真正的代码才使用反引号，不把数学变量都变成代码。

## 块公式

开头和结尾的 `$$` 分别独占一行，顶格书写，前后各留空行。不放入列表缩进、表格单元格或引用块。以下仅为格式示例，不对应任何论文：

```markdown
损失函数的格式示例：

$$
\mathcal{L}(\theta)
= \frac{1}{N}\sum_{i=1}^{N}\ell(f_{\theta}(x_i),y_i)
$$

其中，$N$ 表示样本数。
```

实际笔记中的公式不放在反引号、`latex`/`math` 代码块或 `\[...\]` 中。这里的代码围栏只用于展示 Markdown 源码。

原文编号放在公式前后普通正文中，如「对应原文 Equation (3)」。不自动重编号，不依赖 `\label`、`\ref` 或隐式编号建立定位。

## 多行公式与兼容性

在同一 `$$` 块内用 `aligned`，以 `&` 对齐，以两个反斜杠换行：

```markdown
$$
\begin{aligned}
z_i &= f_{\theta}(x_i) \\
\widehat{y}_i &= g(z_i)
\end{aligned}
$$
```

优先用 KaTeX 支持的常用命令及 `aligned`、`cases`、`bmatrix` 等环境。不复制完整 LaTeX 文档、导言区、宏包命令或未定义自定义宏。论文自定义符号按定义展开且保持含义；不能确认的公式标为待核实，不为渲染成功擅改数学内容。

长公式合理分行，中文解释放在公式外。表格只放简短行内公式；绝对值/范数可用 `\lvert` / `\rvert`、`\lVert` / `\rVert` 避免裸竖线干扰表格。复杂公式移到表格外。

## 交付前检查

检查美元定界符成对、块定界符独占一行且无代码缩进、环境与花括号配对、换行保留两个反斜杠、编号及符号与原文一致。保存实际换行，不把 JSON 中的 `\n` 写成可见文本。

默认交付 `.md` 文件及短说明，不整篇重复到聊天。用户要直接复制源码时用一个外层四反引号 Markdown 代码块保护源码，外层围栏不是笔记内容；内部公式仍用普通 `$` 与 `$$`。

源码格式检查与数学含义核对分开。没有实际在用户思源实例导入时，不声称已验证粘贴或导入效果。即使源码正确，渲染后富文本也可能走不同剪贴板路径，优先源文件导入。
